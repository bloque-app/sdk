# Aprobaciones con passkey para tarjetas, cuentas y API keys

Una persona aprueba con su propia passkey cada operación que inicia y que mueve dinero, crea o desbloquea una forma de gastar, o cambia una cuenta o una credencial. La aprobación ocurre en el portal de identidad de Bloque (`approvalUrl`). Tu app nunca maneja la passkey: comparte el link, espera la aprobación y repite la misma llamada con ella.

El flujo general, los tipos de error y `withApproval` están en [Primeros pasos → Aprobaciones con Passkey](../start/getting-started#aprobaciones-con-passkey). Esta página lista los métodos de tarjetas, cuentas, llaves BRE-B y API keys que aceptan una aprobación, y lo que cambia respecto a las transferencias.

## Qué métodos aceptan `approval`

Cada método de la tabla acepta un argumento `options` con `approval` (el valor que devuelve `waitForApproval()`). La creación de cuentas lo acepta en el mismo `CreateAccountOptions`, junto a `idempotencyKey`.

| Método | Por qué necesita al dueño |
|---|---|
| `accounts.card.create(params, options)` | Emite una tarjeta nueva: una forma nueva de gastar el saldo |
| `accounts.card.activate(urn, options)` / `updateStatus(urn, 'active', reason, options)` | Descongela una tarjeta: se puede volver a gastar |
| `accounts.card.update(params, options)` | Puede cambiar el PIN |
| `accounts.card.updateMetadata(params, options)` | Cambia qué saldo debitan las compras, las reglas de gasto y a dónde va el cashback |
| `accounts.card.tokenizeApple(urn, params, options)` / `tokenizeGoogle(urn, params, options)` | Agrega la tarjeta a una billetera del teléfono |
| `accounts.card.delete(urn, options)` | Elimina la tarjeta |
| `accounts.virtual`, `polygon`, `bancolombia`, `us`: `create(params, options)`, `updateMetadata(params, options)`, `activate(urn, options)` | Abre, cambia o descongela una cuenta |
| `accounts.virtual.delete(urn, options)` / `accounts.polygon.delete(urn, options)` | Elimina una cuenta |
| `accounts.us2.create(params, options)` / `accounts.externalUsBank.create(params, options)` / `externalUsBank.exchangePublicToken(params, options)` | Abre una cuenta o vincula un banco externo |
| `accounts.breb.createKey(params, options)` / `activateKey(params, options)` / `deleteKey(params, options)` | Una llave BRE-B decide a dónde llegan los depósitos, y puede reenviarlos a una billetera |
| `identity.apiKeys.create(params, options)` / `identity.apiKeys.rotate(id, options)` | Crea una credencial que actúa como la persona |

Congelar y deshabilitar (`card.freeze`, `card.disable`, `breb.suspendKey`) nunca piden aprobación: una tarjeta perdida debe poder detenerse de inmediato. Renombrar (`updateName`) tampoco.

El gate de aprobaciones de la API, no el SDK, decide si una llamada pide aprobación, y depende del modo en que lo corre cada despliegue: en `off` o `shadow` no rechaza nada, y en `enforce` le pide la aprobación a la persona dueña de la cuenta (hoy, personas naturales; no empresas ni llamadas entre servicios). Pasa `approval` solo al repetir una llamada que fue rechazada con `BloqueApprovalRequiredError`.

## Ejemplo: emitir una tarjeta

```typescript
import { BloqueApprovalRequiredError, withApproval } from '@bloque/sdk';

const card = await withApproval(
  (approval) =>
    bloque.accounts.card.create(
      { name: 'Mercado' },
      { idempotencyKey: `card-${orderId}`, approval },
    ),
  {
    onApprovalRequired: (error: BloqueApprovalRequiredError) => {
      // Muestra al dueño lo que aprueba (error.summary) y luego el link.
      notifyOwner(error.approvalUrl);
    },
  },
);
```

Mantén el mismo `idempotencyKey` al repetir: la aprobación cubre los campos de la operación, y la llave hace que repetir tras una respuesta perdida llegue a la misma tarjeta.

## Ejemplo: cambiar reglas de gasto

```typescript
const update = (approval?: string) =>
  bloque.accounts.card.updateMetadata(
    { urn: cardUrn, metadata: { priority_mcc: ['5411'] } },
    { approval },
  );

const updated = await withApproval(update, {
  onApprovalRequired: (error) => notifyOwner(error.approvalUrl),
});
```

Repite la llamada con exactamente los mismos parámetros. Otro PIN, otro valor de metadata u otro estado es otra operación y necesita otra aprobación.

## Llaves BRE-B

`breb.createKey`, `activateKey` y `deleteKey` devuelven sus errores como `{ data: null, error }`, salvo los errores de aprobación con passkey (`BloqueApprovalRequiredError`, `BloqueApprovalInvalidError`, `BloqueApprovalExpiredError`, `BloqueApprovalUnavailableError`), que se **lanzan**, como en todos los demás métodos con aprobación. Así puedes esperar la aprobación y repetir la llamada:

```typescript
const key = await withApproval(
  (approval) =>
    bloque.accounts.breb.createKey(
      { keyType: 'BCODE', key: '0016027228', ledgerId },
      { approval },
    ),
  { onApprovalRequired: (error) => notifyOwner(error.approvalUrl) },
);
if (key.error) {
  // Cualquier otro rechazo, devuelto como antes.
}
```

## Errores

Los tipos de error son los mismos que en las transferencias, y todos los métodos de esta página, incluidas las llaves BRE-B, los lanzan: `BloqueApprovalRequiredError` (428), `BloqueApprovalInvalidError` (403), `BloqueApprovalExpiredError` (403) y `BloqueApprovalUnavailableError` (503). Mira la tabla en [Primeros pasos](../start/getting-started#aprobaciones-con-passkey).
