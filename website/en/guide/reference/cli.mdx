# CLI & MCP Server

Use Bloque from your AI agent. One command to set up, then just ask.

## Get Started

```bash
npx @bloque/cli setup
```

The wizard:

1. Logs you in (WhatsApp or Email OTP)
2. Finds your installed AI agents
3. Configures everything automatically

Restart your agent and you're ready.

Already have a JWT? Skip the OTP:

```bash
npx @bloque/cli setup --jwt eyJhbGciOi...
```

## What You Can Ask Your Agent

Once set up, just talk naturally:

- **"Create a card for food expenses, load it with $200"**
- **"I need a one-time $25 card for this website"**
- **"Assign my card to amazon.com"**
- **"Which card should I use for netflix.com?"**
- **"Show me my balances and recent transactions"**
- **"Top up my account with 100,000 COP from my bank"**
- **"Freeze my card"**
- **"Create two cards that share the same budget"**

Your agent handles the accounts, cards, transfers, and reporting behind the scenes.

## How It Works

The CLI installs an [MCP server](https://modelcontextprotocol.io/) that gives your agent access to 44 financial tools — organized in two tiers:

- **Workflows** (14 tools) — high-level operations like "create a card" or "find my card for this website." One call does everything.
- **Primitives** (26 tools) — low-level control when you need it. One tool per SDK method.

Every card is a **crypto card**: it automatically gets a virtual account (holds the balance) and a Polygon address (receives USDC). Top up via crypto, PSE bank transfer, or internal transfer.

**Amounts are always human-readable.** Say "$50" for $50 USD or "100000" for 100,000 COP. No need to think about internal formats.

**Spending restrictions use friendly names.** Say "food" instead of MCC code 5411. Available categories: `food`, `transport`, `ads`, `entertainment`, `health`, `shopping`, `travel`, `subscriptions`.

## Commands

| Command | What it does |
|---------|-------------|
| `bloque setup` | Wizard: log in + install MCP in your agents |
| `bloque login` | Log in via WhatsApp/Email OTP or API key |
| `bloque logout` | Clear your local session |
| `bloque whoami` | Show who you're logged in as |
| `bloque mcp` | Start the MCP server (stdio) |
| `bloque mcp --http` | Start the MCP server over HTTP |

### `bloque setup`

| Option | Description |
|--------|-------------|
| `--api-key <key>` | Secret key (`sk_`) for headless setup |
| `--web` | Authenticate via browser |
| `--jwt <token>` | JWT token (skips OTP) |
| `--sandbox` | Use sandbox instead of production |

### `bloque login`

**OTP mode** (default):

```bash
npx @bloque/cli login
```

**API key mode** (recommended for backend/CI):

```bash
npx @bloque/cli login --api-key sk_live_...
```

**Origin key mode** (legacy):

```bash
npx @bloque/cli login --origin-key your-key --origin your-origin --alias @user
```

### `bloque mcp`

```bash
npx @bloque/cli mcp          # stdio (default)
npx @bloque/cli mcp --http   # HTTP on port 3100
```

## Download Binary (No Node.js Required)

If you don't have Node.js installed, download a standalone binary from [GitHub Releases](https://github.com/bloque-app/sdk/releases):

| Platform | Binary |
|----------|--------|
| macOS (Apple Silicon) | `bloque-darwin-arm64` |
| macOS (Intel) | `bloque-darwin-x64` |
| Linux (x86_64) | `bloque-linux-x64` |
| Linux (ARM) | `bloque-linux-arm64` |
| Windows (x64) | `bloque-windows-x64.exe` |

**macOS / Linux:**

```bash
# Download (replace PLATFORM with your target, e.g. darwin-arm64)
curl -fsSL https://github.com/bloque-app/sdk/releases/latest/download/bloque-PLATFORM -o bloque

# Make executable
chmod +x bloque

# Move to PATH
sudo mv bloque /usr/local/bin/bloque

# Run setup
bloque setup
```

> **macOS Gatekeeper:** If macOS blocks the binary, run:
> `xattr -d com.apple.quarantine /usr/local/bin/bloque`

**Windows:**

Download `bloque-windows-x64.exe` from the release page, rename to `bloque.exe`, and add its directory to your `PATH`.

When running via the binary, `bloque setup` automatically configures your agents to use the binary path instead of `npx`.

## Manual Configuration

If you prefer to configure manually instead of using `bloque setup`:

1. Log in:

```bash
npx @bloque/cli login
```

2. Add this to your agent's MCP config:

```json
{
  "mcpServers": {
    "bloque": {
      "command": "npx",
      "args": ["-y", "@bloque/cli", "mcp"]
    }
  }
}
```

3. Restart your agent.

## Operation Approvals

Some operations that move money need the account owner to approve them with their passkey before they run: transfers, batch transfers, funding a card or account, and swap orders (PSE top-ups, bank cash-outs, BRE-B payouts). When that happens the tool does not fail. It returns the approval request instead:

```json
{
  "status": "approval_required",
  "approvalId": "apr_…",
  "operation": "Transfer 100 USD from did:bloque:… to did:bloque:…",
  "approvalUrl": "https://…",
  "expiresAt": "2026-10-15T15:04:05.000Z",
  "summary": { "operation": "accounts.transfer", "fields": { "amount": "100000000" } },
  "nextStep": "Nothing has moved yet. Share approvalUrl with the account owner…"
}
```

Nothing has moved at this point. Your agent shares `approvalUrl` with you, and you open it and approve with your passkey. The agent then calls `check_approval` with the `approvalId`: it waits up to 45 seconds for your approval and, once you approve, runs the exact same operation and returns `"status": "completed"` with its result. If you have not approved yet it returns `approval_required` again, and the agent can check again until `expiresAt`.

- **Agents that show tool progress** (they send an MCP progress token) get the link as a progress message, and the tool itself waits up to 45 seconds, so a quick approval finishes in the same call.
- **`approval_expired`**: no approval arrived before `expiresAt`. Nothing moved; ask again to get a new link.
- **`approval_rejected`**: the approval was refused, for example because the passkey is not registered for approvals. Nothing moved.
- **`in_progress`**: you approved and the operation is being sent. Checking again returns its result. `check_approval` never sends an approved operation twice: a check while it is in flight waits for it, and a check after it finished returns the same result.
- **`failed`**: the approved operation was sent but returned an error, or its reply was lost, so it may or may not have moved money. The agent checks the account's movements before trying again.
- **Workflows that create something and then fund it** (`create_card`, `create_disposable_card`, `create_account`, `add_spending_category`) still create it; the funding step comes back in `fundingApproval`, to finish with `check_approval`. If that approval expires or is rejected, only the funding step is repeated (`fund_card` or `transfer` on what was already created), never the whole workflow.
- **`check_approval` without an `approvalId`** lists the approvals still pending. They live in the running `bloque mcp` process: restarting it drops them. Finished operations are kept for a while (at least 15 minutes, at most an hour) so a repeated check still gets their result. When the process no longer knows an approval (`approval_not_found`), the agent checks the account's movements before asking again, and never repeats a payment blindly.

The approval link carries a one-time token. Share it only with the account owner: they open it and approve with their own passkey. Agents are told never to open, approve or complete it on the owner's behalf.

## Tools Reference

### Workflows (14 tools)

High-level tools. One call handles multi-step operations.

| Tool | What it does |
|------|-------------|
| `get_profile` | Your identity and KYC status |
| `verify_identity` | Start or check identity verification |
| `create_account` | Create a pocket + Polygon address |
| `create_card` | Full card setup with optional restrictions, website binding, and funding |
| `create_disposable_card` | One-time card with exact funded amount and optional website binding |
| `fund_card` | Top up a card |
| `resolve_card_for_website` | Find which card(s) to use for a given website |
| `assign_card_to_website` | Associate a card with one or more website domains |
| `topup_via_pse` | Load COP via PSE bank transfer |
| `cashout_to_bank` | Cash out USD to a Colombian bank |
| `configure_spending_rules` | Route transactions to different accounts by merchant type |
| `add_spending_category` | Add a spending category to a card |
| `wallet_overview` | All accounts, balances, and recent transactions |
| `card_summary` | Everything about a specific card |

### Primitives (31 tools)

Low-level tools. 1:1 with SDK methods for full control.

| Domain | Tools |
|--------|-------|
| Accounts | `list_accounts`, `get_account`, `get_balance`, `get_all_balances` |
| Virtual | `create_virtual_account`, `list_virtual_accounts` |
| Cards | `create_raw_card`, `list_cards`, `freeze_card`, `activate_card`, `disable_card`, `update_card_metadata`, `rename_card` |
| Polygon | `create_polygon_account`, `list_polygon_accounts` |
| US Bank | `get_us_tos_link`, `create_us_account`, `list_us_accounts` |
| Transfers | `transfer`, `batch_transfer` |
| History | `list_transactions`, `list_account_movements` |
| Swap | `find_rates`, `list_pse_banks`, `create_pse_order`, `create_bank_transfer_order` |
| API Keys | `list_api_keys`, `get_api_key`, `revoke_api_key`, `rotate_api_key` |
| Approvals | `check_approval` |
