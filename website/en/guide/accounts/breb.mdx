# BRE-B

Create and resolve BRE-B payment keys through the SDK.

## Overview

The BRE-B client lets you:

- create a BRE-B key
- associate the key with the account for an existing ledger when `ledgerId` is provided, or create an account automatically when it is omitted
- resolve a BRE-B key before starting a payment flow
- pay to a resolved BRE-B key through `session.swap.breb.create()`
- deposit COP via BRE-B on-ramp through `session.swap.breb.createDeposit()`
- delete a stored key, and — on accounts still backed by the deprecated Passport provider — suspend or activate it

## Create a BRE-B Key

```typescript title="create-breb-key.ts"
const { data, error } = await session.accounts.breb.createKey({
  ledgerId: 'ledger-account-id',
  keyType: 'ALPHA',
  key: '3124581131', // the caller's own verified phone number
  webhookUrl: 'https://api.example.com/webhooks/breb',
  metadata: {
    source: 'checkout',
    // Required with the active provider (Cobre) — not cross-checked
    // against your own verified ID, unlike the holder name.
    holder_id_number: '0000000000',
    holder_id_type: 'cc',
  },
});

if (error) {
  console.error(error.code, error.message);
} else {
  console.log(data?.urn);
  console.log(data?.remoteKeyId);
}
```

### Key types and key value

In the SDK you use `keyType` and `key`. In BRE-B infrastructure those fields commonly appear as `key_type` and `key_value`.

`keyType` defines the format and purpose of the key inside BRE-B, while `key` contains the key value itself. These keys enable fast and secure payments between people and businesses without sharing traditional banking details.

| SDK type (`keyType`) | BRE-B reference (`key_type`) | Description | Example value (`key`) |
| --- | --- | --- | --- |
| `ID` | `ID` | Identification number | `7922089` |
| `PHONE` | `MOBILE` | Mobile phone number | `+573001234567` |
| `EMAIL` | `EMAIL` | Email address | `user@example.com` |
| `ALPHA` | `ALPHA` | Custom alias — must contain a recognizable fragment of your own verified name/phone/email | `3124581131` |
| `BCODE` | `BCODE` | Entity commercial code | `0012345678` |

:::note
The `keyType` + `key` combination must be unique across the BRE-B infrastructure. The platform validates this uniqueness.
:::

:::warning Identity verification required
Creating a BRE-B key requires a KYC-verified identity — otherwise `createKey()` fails with `E_BREB_IDENTITY_NOT_KYC_VERIFIED`. For `keyType: 'ALPHA'` specifically, `key` must also *contain* a recognizable fragment of your own name, last name, phone, or email (normalized) — not an exact match, so e.g. `"MiguelBBlo001"` (name + abbreviated last name + a number) is fine, but a value with no connection to your own data, like a bank or business name, fails with `E_BREB_KEY_VALUE_NOT_VERIFIED`. This doesn't apply to `ID`/`PHONE`/`EMAIL`/`BCODE`, which either are your own rail-verified identifier or (for `BCODE`) not personal data at all. `displayName` is Passport-only and ignored with the active provider (Cobre) — the displayed name is always your own verified name, not a value you supply.
:::

:::warning `holder_id_number`/`holder_id_type` required in `metadata`
With the active provider (Cobre), `createKey()` fails with `E_COBRE_HOLDER_REQUIRED` unless `metadata.holder_id_number` and `metadata.holder_id_type` (e.g. `'cc'`) are supplied. Unlike the holder's name (always derived from your verified identity), these are **not** cross-checked against your own verified ID — whatever you pass is trusted as-is. Confirmed live: this fails even for an otherwise fully KYC-verified identity if omitted.
:::

## Create Result

```typescript title="types.ts"
type BrebOperationResult<T> = {
  data: T | null;
  error: {
    code: string | null;
    message: string;
  } | null;
};
```

`createKey()` returns `{ data, error }`. On success, `error` is `null`. On failure, `data` is `null`.

If you pass `ledgerId`, the BRE-B key is associated with the account for that ledger. If you omit it, the SDK creates an account automatically.

When `createKey()` succeeds, `data` contains the created BRE-B key and its associated account:

## Resolve a BRE-B Key

```typescript title="resolve-breb-key.ts"
// with explicit key type
const { data, error } = await session.accounts.breb.resolveKey({
  keyType: 'PHONE',
  key: '3015550127',
});

// keyType omitted — BRE-B infers it from the key value
const { data, error } = await session.accounts.breb.resolveKey({
  key: '3015550127',
});

if (error) {
  console.error(error.code, error.message);
} else {
  console.log(data?.resolutionId);
  console.log(data?.owner?.name);
  console.log(data?.account?.accountNumber);
}
```

## Pay to a BRE-B Key

Resolve the recipient key first, then create a BRE-B payout order:

```typescript title="pay-to-breb-key.ts"
const resolution = await session.accounts.breb.resolveKey({
  keyType: 'PHONE',
  key: '3015550127',
});

if (resolution.error || !resolution.data) {
  throw new Error(
    resolution.error?.message ?? 'Failed to resolve BRE-B key',
  );
}

const rates = await session.swap.findRates({
  fromAsset: 'COPM/2',
  toAsset: 'COP/2',
  fromMediums: ['kusama'],
  toMediums: ['breb'],
  amountSrc: '10000000',
});

if (rates.rates.length === 0) {
  throw new Error('No swap rates available for BRE-B payout.');
}

const result = await session.swap.breb.create({
  rateSig: rates.rates[0].sig,
  amountSrc: '10000000',
  depositInformation: {
    resolutionId: resolution.data.resolutionId,
  },
  args: {
    sourceAccountUrn: 'did:bloque:account:breb:demo-account-id',
  },
});

console.log(result.order.id, result.order.status);
```

## Deposit COP via BRE-B (On-Ramp)

Deposit COP through a one-time BRE-B key; the escrow pays out DUSD on Kusama to your account.

```typescript title="breb-deposit-onramp.ts"
const rates = await session.swap.findRates({
  fromAsset: 'COP/2',
  toAsset: 'DUSD/6',
  fromMediums: ['breb'],
  toMediums: ['kusama'],
  amountSrc: '20000000',
});

const result = await session.swap.breb.createDeposit({
  rateSig: rates.rates[0].sig,
  amountSrc: '20000000',
  depositInformation: {
    urn: 'did:bloque:account:breb-user-001',
  },
  args: {},
});

const how = result.execution?.result.how;
if (how?.type === 'BREB_DEPOSIT') {
  console.log('Send COP to BRE-B key:', how.keyType, how.keyValue);
  console.log('Amount:', how.expectedAmount ?? how.amount, how.currency);
}
```

### Partial payments

If the payer sends less than the order amount, the graph stays paused on the **same** key. Multiple BRE-B transfers are summed. `how.depositStatus` becomes `'partial'` and `remainingAmount` shows how much COP is still required:

```typescript title="breb-deposit-partial.ts"
if (how?.type === 'BREB_DEPOSIT' && how.depositStatus === 'partial') {
  console.log('Received:', how.receivedAmount);
  console.log('Still need:', how.remainingAmount);
  console.log('Top up to same key:', how.keyValue);
}
```

Poll `user.swap.listOrders({ graphId: result.order.graphId })` or use `swap.order.*` webhooks to detect when a partial payment lands — the `createDeposit` response does not update asynchronously.

### CreateBrebDepositParams

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `rateSig` | `string` | Yes | Rate signature from `findRates` |
| `amountSrc` | `string` | Conditional | Source COP amount (required if `type` is `'src'`) |
| `depositInformation.urn` | `string` | Yes | Account URN to credit with DUSD on Kusama |
| `args` | `Record<string, unknown>` | No | Pass `{}` to auto-execute and receive the BRE-B key |

### ExecutionHowBrebDeposit

When `args` is provided, the order pauses with a `BREB_DEPOSIT` payload:

```typescript title="types.ts"
interface ExecutionHowBrebDeposit {
  type: 'BREB_DEPOSIT';
  medium: 'breb';
  keyType: string;
  keyValue: string;
  amount: string;
  currency: 'COP';
  reference: string;
  depositAccountUrn: string;
  expectedAmount?: string;
  receivedAmount?: string;
  remainingAmount?: string;
  depositStatus?: 'awaiting' | 'partial';
}
```

Show `keyType` and `keyValue` so the payer can send COP via their bank's BRE-B app. The swap graph resumes automatically when inbound payments settle. Underpayments keep the same key — send the `remainingAmount` to `keyValue` until `receivedAmount >= expectedAmount`.

## Suspend a BRE-B Key

:::warning Not supported on Cobre-backed accounts
`suspendKey` fails with a hard error (`501`) on BRE-B accounts backed by Cobre, Bloque's active provider — Cobre's key-freeze feature is in beta and unavailable in production. There is no way to freeze a Cobre-backed key while keeping it able to be reactivated; the only available operation is `deleteKey`, which is terminal. Only accounts still backed by the deprecated Passport provider support suspend/activate.
:::

```typescript title="suspend-breb-key.ts"
const { data, error } = await session.accounts.breb.suspendKey({
  accountUrn: 'did:bloque:account:breb:demo-account-id',
});

if (error) {
  console.error(error.code, error.message);
} else {
  console.log(data?.status);
}
```

## Activate a BRE-B Key

:::warning Not supported on Cobre-backed accounts
Same limitation as `suspendKey` above: `activateKey` fails with a hard error (`501`) on Cobre-backed accounts. Only accounts still backed by the deprecated Passport provider support this call.
:::

```typescript title="activate-breb-key.ts"
const { data, error } = await session.accounts.breb.activateKey({
```

## Error Handling

BRE-B operations return minimal errors:

```typescript title="error-handling.ts"
const { data, error } = await session.accounts.breb.createKey({
  ledgerId: 'ledger-account-id',
  keyType: 'PHONE',
  key: '3015550184',
});

if (error) {
  if (error.code === 'U808') {
    console.log('Key already registered');
  }

  console.error(error.message);
}
```

`createKey()` can also fail before it ever reaches the provider:

| `error.code` | Meaning |
| --- | --- |
| `E_BREB_IDENTITY_NOT_KYC_VERIFIED` | The caller identity isn't KYC-verified. |
| `E_BREB_KEY_VALUE_NOT_VERIFIED` | `keyType: 'ALPHA'` only: `key` isn't a verified combination of your own name/last name/phone/email. |

## Notes

- `holder_urn` is taken from the connected SDK session
- if `ledgerId` is provided, the account is linked to that ledger
- if `ledgerId` is omitted, a ledger is created automatically
- key suspension updates the account with `PATCH /api/accounts/:accountUrn` and `status: 'frozen'` — Passport-backed accounts only, fails with `501` on Cobre-backed accounts
- key activation updates the account with `PATCH /api/accounts/:accountUrn` and `status: 'active'` — Passport-backed accounts only, fails with `501` on Cobre-backed accounts
- key deletion updates the account with `PATCH /api/accounts/:accountUrn` and `status: 'deleted'` — supported on both providers, but terminal on Cobre-backed accounts (no way back to `active` short of creating a new key)
- BRE-B payouts are created through `session.swap.breb.create()`
- BRE-B on-ramp deposits are created through `session.swap.breb.createDeposit()`
